# 数据与批准约定

## 内容状态流

- `raw.json`：忠实保存消息、附件、文件散列和来源，不做事实判断。
- `draft.json`：结构化内容草案；允许未知、冲突和助理建议。
- `approved.json`：用户确认后冻结的内容事实；批准绑定草案 SHA-256。

## 排版状态流

- `render-plan.json`：把已批准内容映射成 1～6 个教学行，不增加新事实。
- `approved-render-plan.json`：用户确认每行标题、文字、图片编号和图文位置后的冻结版本；同时绑定 `approved.json` 的 SHA-256。

内容批准不能代替排版批准，排版批准也不能改变内容事实。修改内容、图片文件、图片用途、模板版本或图文映射后，对应旧批准失效。

## 来源与事实

每个关键字段使用：

```json
{"value":"设备启动后不转","status":"user_stated","source_refs":["MSG-008"]}
```

`source_refs` 必须存在于顶层 `source_index`；规则推导使用登记过的 `RULE:*` 来源。采用图片必须含原文件路径、`source_sha256`、显示宽高、用途、对应步骤和确认状态。同名图片内容发生变化时，文件散列校验必须失败。

## 版本

内容 schema 为 `1.1`；标准模板为 `steven-opl-standard/1.1.0`。旧任务不得静默升级，应重新生成排版计划并确认。培训记录不属于输入字段，标准模板始终留空。
