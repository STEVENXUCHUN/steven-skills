# 采集与动态补问

## 输入边界

可接受聊天文字、维修记录、现场图片、已有文件及用户口述。脚本只读取显式传入的数据，不假设能访问当前聊天。

为每条消息分配 `message_id`，记录角色、时间、文字和附件 ID；为每个附件分配稳定 `asset_id` 并保留原文件名、路径、MIME、散列和来源消息。

## 首轮判断

先从已有材料判断：

1. 想讲的单点是什么；
2. 属于哪种课型；
3. 是否混入多个独立主题；
4. 图片用途是否已由用户说明；
5. 哪些缺口会阻碍草案或验收。

## 补问优先级

每轮只问 1～3 个最关键问题：

1. 本课只讲哪一个点；
2. 对象、现象或目标是什么；
3. 实际执行了什么关键动作；
4. 如何检查动作有效；
5. 每张图片是什么、用于说明什么；
6. 安全前提、易错点和验收结果；
7. 冲突信息以哪个版本为准。

已经明确的内容不重复询问。非关键内容可标为 `unknown`，不要为了填满模板诱导用户猜测。

## 图片提问

收到图片后先按发送顺序列出 `IMG-001`、`IMG-002`……，询问每张图：

- 图中是什么；
- 想用来说明什么；
- 对应哪个步骤或章节；
- 是否允许裁剪或调向（默认不允许）。

不得先识图后让用户“确认猜测”。只有用户明确要求识别时，才可使用识图/OCR，并将结果标为 `assistant_suggested`，等待确认。

## 停止补问

满足以下条件即可形成草案：主题单一、关键操作可执行、至少有检查或限制说明、图片均有用途或明确排除、关键冲突已解决。无法补齐时，列出限制并让用户选择继续做限制版草案或暂停。
